# loud-cron 0.1.0

Released 2026-11-22.

- GitHub release: <https://github.com/WJDdidi-1/loud-cron/releases/tag/0.1.0>
- Tag `0.1.0` at commit [`67db9f3`](https://github.com/WJDdidi-1/loud-cron/tree/67db9f36fde6033d32a027901fb5007eb2a9eca1)
- npm: not published yet

`0.1.0` is the first tagged release of loud-cron. It is a pre-runner MVP: a
strict, local validator for cron job files. It parses and reports; it does not
schedule or execute jobs. The runner work is listed under
[Not in this release](#not-in-this-release).

## Install

There is no npm package yet. Install from a checkout with Node.js 18 or newer:

```sh
git clone https://github.com/WJDdidi-1/loud-cron.git
cd loud-cron
npm install -g .
loud-cron --version
```

The tagged source is also available as a zip or tarball from the
[release page](https://github.com/WJDdidi-1/loud-cron/releases/tag/0.1.0).

## What is in this release

`loud-cron check <jobs.json>`:

- Parses classic five-field cron expressions (`minute hour day-of-month month
  day-of-week`), including lists, ranges, steps, month and weekday names, and
  the `@yearly`/`@monthly`/`@weekly`/`@daily`/`@hourly` aliases.
- Rejects truncated or over-long expressions instead of guessing. Seconds are
  not supported, so a six-field expression is an error.
- Rejects out-of-range values, reversed ranges, bad steps, unknown aliases, and
  extended syntax it does not implement.
- Requires every job to have a non-empty, unique `id`, a schedule, and a
  non-empty `command`.
- Rejects unknown top-level and per-job fields, so a typo such as `commnd` is
  reported instead of silently ignored.
- Validates the optional fields `description`, `cwd`, `env`, `timeoutMs`,
  `timeout`, `enabled`, `shell`, and `overlap`.
- Accepts a `{ "jobs": [ ... ] }` document or a bare array of jobs, with an
  optional top-level `version`.
- Reports every problem found in one pass as JSON, with stable error codes and
  a `path` such as `jobs[2].schedule`.
- Exits `0` for a valid file, `1` for an invalid or unreadable file, and `2`
  for a usage error. `--json` is accepted; JSON is already the default for
  `check`.

The package has no runtime dependencies. The full field, cron-syntax, and
error-code reference is in
[`docs/jobs-file.md`](https://github.com/WJDdidi-1/loud-cron/blob/0.1.0/docs/jobs-file.md).

## Not in this release

- `loud-cron run` does not exist. No command from a jobs file is executed.
- There is no scheduler loop or `tick`, so nothing runs on a schedule.
- There is no durable run ledger, no reconciliation of missed runs, and no
  reporting of hung jobs.
- `timeout`, `timeoutMs`, `overlap`, `enabled`, and `shell` are validated as
  fields but are not applied by a runner.
- There is no `doctor` command, `--on-failure` hook, or notification channel.
- The package is not published to npm.

These are planned, not current behavior. If you need a runner today, keep using
cron, systemd timers, or your platform scheduler, and use `loud-cron check` to
guard the job definitions before they get there.

## Verify this release

From the checkout:

```sh
npm test
```

The suite has 22 tests covering the cron parser, the job-file validator, and
the CLI. All 22 pass on the tagged commit; CI runs the same suite on Linux,
macOS, and Windows with Node 18, 20, and 22.

```sh
npm run check:example
```

validates `examples/jobs.json` and exits `0`.

```sh
node ./bin/loud-cron.mjs check examples/invalid-jobs.json
```

exits `1` and reports all six problems in the file. The exact report is in
[`examples/README.md`](https://github.com/WJDdidi-1/loud-cron/blob/0.1.0/examples/README.md).

```sh
node ./bin/loud-cron.mjs --version
```

prints `0.1.0`.

## Compatibility

- Node.js 18 or newer.
- Classic five-field cron expressions only; seconds are not supported.
- This is the first release, so there are no upgrade notes.

When npm distribution is enabled, the published version will get a `v`-prefixed
